# 个人语料档案

档案是一份 Markdown，存在用户本机：

```bash
node <PLUGIN_ROOT>/scripts/voice.mjs path     # 档案路径
node <PLUGIN_ROOT>/scripts/voice.mjs show     # 打印档案；没有档案时说明怎么建
node <PLUGIN_ROOT>/scripts/voice.mjs note "用户说：不要用『赋能』，他一般说『帮上忙』"   # 追加一条对话里学到的
node <PLUGIN_ROOT>/scripts/voice.mjs collect  # 把用户在 DeepSeek 里发过的消息整理成学习素材
```

## 什么时候读

替用户写任何要署他名字的文字之前：文章、改稿、PPT 讲稿和页面文案、卡片标题和正文、去 AI 味。先运行 `voice.mjs show`，有档案就按档案写，没有就照常写，不要为此打断用户。

## 建档：从样本学

1. 样本有两种来源，可以一起用：
   - **聊天记录（默认）**：用户在 DeepSeek 里发过的消息，尤其是大段内容。用户从插件页面点「从我的 DeepSeek 对话学习」时，素材已经整理好，路径写在消息里；否则先运行 `voice.mjs collect`。素材里混着指令和随手的短句：只从用户自己写的成段文字里提炼写作习惯，指令式的句子（「帮我改一下」「做成 PPT」）只用来看措辞偏好，不当成文风样本。
   - **文章**：用户写过的文章、帖子或讲稿（文件、链接或直接贴）。
   成段文字加起来少于 3 篇文章的量时先建，标明「样本少，置信度低」，以后再补。
2. 逐条提炼可观察的特征，**每条都要能在样本里找到至少两处证据**，并摘一小段原文。找不到证据的不要写，不要凭印象补全：
   - 句子长短和节奏：长短句怎么交替，段落一般几句。
   - 开头和结尾的习惯：从场景、结论还是问题开头；结尾是否总结、是否抛问题。
   - 人称和称呼：「我 / 我们 / 你 / 大家」，怎么称呼读者。
   - 常用词和口头禅（写出现次数）、明显不用的表达（例如从不说「赋能」「抓手」）。
   - 确定程度：是直接下判断，还是常留余地；怎么表达不确定。
   - 标点：破折号、引号、感叹号、省略号的用法，中英文之间是否留空格，数字写法。
   - 中英混排：哪些词保留英文，哪些翻译。
   - 幽默和情绪：有没有自嘲、反问、口语化的插话。
3. 摘 2–3 段最能代表语气的原文（每段不超过 150 字），放在档案末尾当参照。
4. 按下面的结构写进档案（路径用 `voice.mjs path` 拿到，直接编辑这个文件），写完把档案内容给用户过目，用户说哪条不对就删改哪条。

```markdown
# 语料档案
更新：YYYY-MM-DD · 样本 N 篇（列出标题）

## 节奏与结构
## 人称与称呼
## 常用词 / 不用的词
## 判断与语气
## 标点与混排
## 对话中学到的
## 原文参照
```

## 在对话里持续学

用户纠正措辞时（「别用这个词」「我一般这么说」「太正式了」），在照改之外，用 `voice.mjs note` 记一条，写清原话和改法。同一条规律出现第二次时，把它从「对话中学到的」挪进对应的小节。

## 用档案写作时

- 档案描述的是用户的习惯，不是要堆砌的特征：口头禅按样本里的频率用，不要每段都放。
- 和去 AI 味（humanizer-zh）一起用时，以档案为准：用户自己就爱用的表达，即使看起来像模板，也保留。
- 档案只在本机，不要把它的内容发到别处；用户要求删除时直接删文件。
