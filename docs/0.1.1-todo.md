# 0.1.1

来自 2026-10-31 桌面版实测（另一台电脑，DSH 桌面版 + DeepSeek-V4.1-Flash，会话 13f3dcee「介绍丝绸之路 PPT」）。

## 已修

1. **PPT skill 的 Step 0「检查更新」在插件里必然失败。** 插件里的 skill 是快照，没有 `.git`，模型每次都跑 `git fetch` 报 `not a git repository`，再花一轮向用户解释。`lib/skills.js` 的 `REWRITES` 在加载时把这一步换成「插件里跳过」；测试检查每条替换都命中、所有 skill 正文里都没有 git 命令。
2. **语气档案为空时，模型把它当成检查结果报告给用户。** 空状态文案改成「这不是错误，照常写，不用向用户报告」（`lib/voice.js` 的 `NO_PROFILE`）；脚本、skill、页面统一叫「语气档案」。
3. **作品登记被沙箱拦下（EPERM），要用户授权。** 模型的 bash 只能写工作区，作品库和语气档案在 `$DSH_HOME/guizang-design`。改成插件注册的两个工具 `guizang_library_add`、`guizang_voice`（`lib/tools.js`），在 Host 进程里执行；skill 附注和 guizang-voice skill 都改用工具，脚本留给终端手动用。
4. **桌面版的数据目录。** 会话日志显示桌面版的 home 就是 `~/.dsh`（插件装在 `~/.dsh/profiles/desktop`），和插件的默认值一致；改用工具后，模型写的目录和插件页面读的目录由同一个进程决定，不会再分叉。

## 不是插件的问题

- **`DeepSeek Messages stream: tool input is invalid JSON`（MALFORMED_RESPONSE）。** 模型调用 `ask_user_question` 时，在 JSON 字符串里写了 `偏"从历史看今天"`，中文引语用了没转义的英文双引号，参数在第 866 个字符处断开。是模型输出的问题，用户再发一条就好了。

## 待验证

- 两个工具在真实会话里是否不弹审批。按 dsh 的设计，只有沙箱里的 bash / 文件 / 终端会请求审批，插件工具不会，但没有用真实模型跑过。
- 网页导出 PDF / 长图（`guizang-page-skill/scripts/export.mjs`，puppeteer）在桌面版沙箱里能不能启动 Chrome。模型这次自己起的 headless Chrome 在沙箱里一启动就崩，要加 `--no-sandbox --disable-gpu`；卡片出图用的 Playwright 默认就带 `--no-sandbox`，puppeteer 不带。

## 交给 PPT skill 仓库（模型在测试里整理的问题清单）

- `window.__playSlide(i)` 只播放动画不翻页，没有按页跳转的接口（建议暴露 `__goTo(i)` 或在文档写清）。
- 1280×720 这类矮屏上，四宫格和三栏页的内容会压到页脚（建议模板加 `@media (max-height: 780px)` 的紧凑档）。
- 模板默认带 lucide 脚本，页面没用图标时也加载。
- 模板引用 `./assets/motion.min.js`，构建 deck 时没有一起拷贝，离线时静默回退到 CDN。
